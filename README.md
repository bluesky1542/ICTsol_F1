## 開発するアプリ

疲労度や予定状況を考慮して、利用者が取り組みやすいタスクを提案するスマホアプリです。

## 技術構成

- スマホアプリ：Expo + React Native + TypeScript
- バックエンド：Python + FastAPI
- 生成AI：Python SDK

詳しい方針は [`docs/開発方針.md`](docs/開発方針.md) を確認してください。

## 構成

- `mobile/`: スマホアプリ（Webでの動作確認にも対応）
- `backend/`: API サーバー
- `docs/`: 開発方針・仕様書・議事録

現在はアカウント登録・ログイン、ユーザー別のタスク・疲労度・予定管理、SQLiteへの保存、生成AI提案を実装した開発版です。端末カレンダーの選択・読み取りと予定時間の取り込みに対応し、Webでは手入力できます。公開運用向けのHTTPS・パスワード再設定・メール確認等は今後の作業です。

## 必要な環境

- Node.js：24系 LTS（24.3.0以上を使用し、チームでバージョンを揃える。今回の検証環境は26.0.0）
- Python 3.10 以上（動作確認環境は 3.13）
- 実機で端末カレンダーを使う場合：開発ビルド（Expo Go非対応）。詳細は後述。

## 起動方法

### バックエンド

```bash
cd backend
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

各コマンドはリポジトリ直下から開始してください。Pythonの実行コマンドは自分の環境に合わせて変更します（`python3 --version` で確認）。Windows PowerShellでは仮想環境の有効化に `.venv\Scripts\Activate.ps1` を使います。

PCで `http://localhost:8000/api/health` を開くと応答を確認できます。API一覧は `http://localhost:8000/docs` にあります。

### スマホアプリ

別のターミナルで実行します。

```bash
cd mobile
npm ci
```

`mobile/.env.example` を同じフォルダに `.env` という名前でコピーし、接続先を設定します。

```dotenv
EXPO_PUBLIC_API_BASE_URL=http://192.168.1.100:8000
```

`192.168.1.100` は例です。PCのネットワーク設定に表示されるLAN内IPアドレスに置き換えてください。

- 実機：PCのLAN内IPを指定し、スマホとPCを同じWi-Fiへ接続します。まずスマホのブラウザで `http://PCのIP:8000/api/health` が開けることを確認してください。
- Android標準エミュレーター：`http://10.0.2.2:8000`
- iOSシミュレーター・PCブラウザ：`http://localhost:8000`

設定後、`mobile/` で実行します。

```bash
npm start
```

起動後はアカウント作成またはログイン画面が開きます。接続先を変更した場合は開発サーバーを再起動してアプリを再読み込みします。Expo Goは基本画面の確認用で、端末カレンダーには下記の開発ビルドが必要です。

Webで確認する場合は `mobile/` で実行します（`.env` がない場合、Webのみ `http://localhost:8000` を使用）。

```bash
npm run web
```

表示されたURLをブラウザで開いてください。

## 開発時の確認

バックエンドのテストは `backend/` で以下を実行します。テストは一時DBと偽のAI応答を使用し、実際のAPI利用料金は発生しません。

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

`mobile/` で `npm run typecheck` と `npx expo install --check` を実行します。

`.env` と `.venv/` はGitの管理対象外です。`EXPO_PUBLIC_` の設定値はアプリに含まれるため、生成AIのAPIキーは必ずバックエンド側で管理します。

Webの許可元は `CORS_ORIGINS` で設定します（初期値はlocalhost/127.0.0.1の8081番）。HTTP通信はローカル開発用で、テスト専用のパスワードを使ってください。外部公開前にHTTPS、認証の運用・復旧手段、依存関係の監査対応を整備してください。

## ログイン・ユーザー別管理

- ユーザー名は英数字・`_`・`-` の3〜40文字（大文字小文字を区別しない）、パスワードは12〜128文字です。
- パスワードはソルト付きscryptハッシュで保存します。トークンもDBにはSHA-256ハッシュだけを保存します。
- セッションの有効期限は24時間。トークンは画面のメモリだけに保持するため、更新・アプリ終了後は再ログインが必要です。
- ログアウトするとサーバー側でも該当セッションを失効します。登録・ログインは15分間でユーザー名ごと10回、接続元IPごと60回までです。
- タスク、疲労度、取り込んだ予定、AI提案の候補はログインしたユーザーだけに限定されます。
- 旧版の匿名タスク（`user_id IS NULL`）と `conditions` テーブルは削除せず残します。新規アカウントへの自動引き継ぎはしません。所有者を確認して移す管理機能は未実装です。

## カレンダー連携

端末に登録されたカレンダーから選択して、今から7日分の予定時間を取り込みます。Google/Apple等のカレンダーが端末へ同期済みなら対象にできますが、Google Calendar API等への直接OAuth連携ではありません。

1. `mobile/` で `npm ci` を実行する。
2. Xcode（iOS/Mac）またはAndroid Studioを用意し、端末を接続する。
3. `npx expo run:ios --device` または `npx expo run:android --device` で開発用アプリをビルドする。iOS実機は署名設定が必要です。
4. アプリでログインし、「端末のカレンダーを選ぶ」で読み取りを許可する。
5. 対象を選択して「選択した予定を取り込む」を押す。

SDK 57の `expo-calendar` は[公式案内](https://docs.expo.dev/versions/v57.0.0/sdk/calendar/)の通りExpo Goでは利用できません。ネイティブ権限は `app.json` のプラグインに設定済みです。実機での権限確認・読み取り動作は未検証です。

- 同期はボタン操作時のみ。自動同期・端末カレンダーへの書き込みはありません。
- サーバーには識別子と開始・終了時刻だけを送り、予定名・説明・参加者を送りません。AIにはカレンダーの予定そのものを渡さず、計算した空き時間だけを使います。
- 取り込みは本人の予定スナップショット全体を置換します。手入力予定も置換されるため画面で明示しています。
- 終日予定は終日を予定ありとして扱い、キャンセル・空き時間として登録されたイベントは除外します。連携解除はサーバー側の取り込みデータだけを削除します。
- Webでは日時（端末の現地時刻）を手入力できます。カレンダーから取り込む場合も含め、予定変更後は再取り込みが必要です。
- 「取り込んだ予定を考慮する」が有効なとき、提案時間は入力時間と次の予定までの時間の短い方です。予定の最中は0分になります。同期範囲外・24時間以上前の取り込みは再同期を要求します。

## AI提案を使う

1. `backend/.env.example` を `backend/.env` としてコピーする。
2. `OPENAI_API_KEY` と `OPENAI_MODEL` を設定する。モデルIDは自分のOpenAI APIアカウントで利用できる、Responses APIとStructured Outputsに対応したものを指定する。
3. バックエンドを再起動し、画面の「最新の状態に更新」を押す。
4. タスクと今の調子を登録し、空き時間・場所を入力して「AIの提案を取得」を押す。

APIキーはチャットやGitHubに貼らず、バックエンドの `.env` にだけ設定してください。APIキー・モデルが未設定でもタスク管理は利用できますが、AI提案は無効になります。

AIには未完了かつ所要時間・場所に合う候補を最大30件送信し、最大3件の代替候補と理由、休息の理由を受け取ります。入力した状態をそのまま利用する初期版で、5段階の疲労度推定は未実装です。AIは[公式のStructured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)を使用し、候補外ID・重複・拒否・タイムアウトはエラーとして扱います。

提案取得時にはタスク名・締切・優先度・集中度・所要時間・場所・入力した調子をOpenAIへ送信し、API利用料金が発生します。候補がない場合はAIを呼び出さず、その旨を表示します。エラー時に偽のAI提案を表示することはありません。

データは `backend/data/app.sqlite3` に保存され、Gitには含まれません。保存先はサーバーの環境変数 `DATABASE_PATH` で変更できます。タスク・調子は永続化しますが、提案と「取り組む／休息」の選択は画面内のみです。
