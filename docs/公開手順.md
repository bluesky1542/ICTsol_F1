# チーム向けWeb版の公開

画面とPython APIをひとつのDockerコンテナで配信します。公開URLを開いてアカウントを作成すると、PCやスマホのブラウザから利用できます。端末カレンダーの読み取りはネイティブ版のみで、Web版では予定を手入力します。

## ローカルで公開用構成を確認

リポジトリ直下で実行します（Dockerが必要）。

```bash
docker build -t ictsol-f1 .
docker run --rm -p 8000:8000 -v ictsol-f1-data:/app/data ictsol-f1
```

`http://localhost:8000` で画面とAPIを確認できます。データはDockerの名前付きボリュームに保存します。AIを使う場合はサーバーの環境変数 `OPENAI_API_KEY` と `OPENAI_MODEL` を設定してください。キーをDockerfileやGitに記載しないでください。

Docker Compose 2.24以降なら、`backend/.env`を読み込み、保存用ボリュームも設定できます。

```bash
docker compose up --build -d
docker compose ps
```

停止は `docker compose down`、再開は `docker compose up -d` です。`down -v` は保存データも削除するため、通常の停止では使わないでください。この設定はPC内での確認用です。外部公開にはHTTPSを提供する公開先が必要です。

## Dockerなしで公開用の動作を検証

`mobile/`でWeb版を書き出します。デモを無効にし、APIを同じURLに向けます。

```bash
EXPO_PUBLIC_DEMO_MODE=0 EXPO_PUBLIC_API_BASE_URL=/ npx expo export --platform web
```

次に`backend/`で確認します。検証は一時DBを使用し、実際のAIを呼びません。

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python verify_release.py
```

ブラウザで確認する場合、`backend/`で以下を実行し、`http://localhost:8002`を開きます。これは通常の保存先を使うため、登録したデータが残ります。

```bash
WEB_DIST_PATH=../mobile/dist .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

## Render無料プラン＋Supabase無料DBに公開する場合

### Supabaseを用意する

1. [Supabase](https://supabase.com/)に登録し、Freeプランでプロジェクトを作成する。DBパスワードは手元で管理する。
2. ダッシュボードの「Connect」で「Session pooler」の接続URIを取得する。ポート5432のIPv4対応URLを使う。
3. URLのパスワード部分を自分のDBパスワードに置き換え、`sslmode=require`を指定する。パスワードにURLで特殊な意味を持つ文字がある場合はURLエンコードする。
4. 接続URLはRenderの秘密環境変数にだけ設定する。チャット・GitHub・mobileの設定へ貼らない。

アプリ起動時に `ictsol` スキーマと必要なテーブルを作成します。`public` スキーマの既存テーブルには触れません。`ictsol` をSupabaseのData APIの公開スキーマに追加しないでください。ブラウザはFastAPIにログインしてデータを取得し、Supabase Authやブラウザ向けのSupabase SDKは使用しません。

### Renderを用意する

1. [Render](https://render.com/)に登録し、GitHubの `bluesky1542/ICTsol_F1` を接続する。
2. `render.yaml`があるブランチから「New → Blueprint」を作成する。定義済みのWeb ServiceはFreeプランで、永続ディスクは追加しない。
3. `DATABASE_URL` にSupabaseのSession pooler接続URLを設定する。
4. AIを使う場合は `OPENAI_API_KEY` と `OPENAI_MODEL` を設定する。後から設定する場合は空欄にする。Blueprint画面で空欄が受け付けられない場合は、以下の手動設定を使う。
5. 作成前にFreeプランであることを確認し、デプロイする。
6. 発行されたHTTPS URLで登録・タスク保存・再ログインを確認し、URLをチームに共有する。

手動でWeb Serviceを作る場合はRuntimeをDocker、Dockerfileをリポジトリ直下の `Dockerfile`、Root Directoryを空欄、Health Check Pathを `/api/health`、Instance TypeをFreeに設定します。環境変数に `DATABASE_URL` と `REQUIRE_DATABASE_URL=1` を追加してください。公開環境ではDB設定がないままSQLiteへ保存しないよう、起動を止めます。

`DATABASE_URL`が指定されている場合、SQLiteの保存先やRenderのディスクは使用しません。Renderの再起動後もSupabaseのデータを使用します。ローカルSQLiteの記録は自動移行されず、公開先では新たにアカウントを作成します。

Render無料プランは15分間アクセスがないと休止するため、次のアクセス時は起動を待つ場合があります。Supabase無料プランも低活動時に一時停止されることがあります。無料枠の容量・利用量を超える前に管理画面を確認してください。生成AI APIの料金は別です。

ローカルのSQLiteを使うDocker構成ではボリュームを保持してください。DBバックアップはSupabase等の公開先の運用手順で別途用意します。

## PostgreSQLの開発検証

`backend/`で、テスト専用の `ictsol_test` DBを指定して実行できます。接続先に実データのDBを指定しないでください。

```bash
TEST_DATABASE_URL='postgresql://postgres:テスト用パスワード@localhost:5432/ictsol_test?sslmode=disable' .venv/bin/python -m unittest discover -s tests -v
```

`.github/workflows/test.yml`はPR時に一時PostgreSQLを立ち上げて同じテストを実行します。上のSSL無効指定はローカルのテストDB専用です。Supabaseへの公開接続ではSSLを有効にしてください。

公式手順：[Render無料プラン](https://render.com/docs/free)、[Blueprint](https://render.com/docs/blueprint-spec)、[SupabaseのDB接続](https://supabase.com/docs/guides/database/connecting-to-postgres)、[Supabaseの無料枠](https://supabase.com/docs/guides/platform/billing-on-supabase)、[一時停止](https://supabase.com/docs/guides/platform/free-project-pausing)。
