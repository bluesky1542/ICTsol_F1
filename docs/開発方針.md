# ICTsol F1 開発方針

## アプリ概要

疲労度や予定状況を考慮して、利用者が取り組みやすいタスクを提案するスマホアプリを開発する。

## 技術構成

- スマホアプリ：Expo + React Native + TypeScript
- バックエンド：Python + FastAPI
- 生成AI：Gemini REST API（無料枠を利用可能）
- データベース：ローカル試作版では SQLite を使用

## 通信構成

```text
スマホアプリ → FastAPI → 生成AI API / データベース
```

APIキーはスマホアプリに置かず、バックエンドで管理する。

## 最初の完成条件

- スマホアプリが起動する
- FastAPI が起動する
- スマホアプリから FastAPI の `/api/health` または `/api/hello` を呼び出せる
- チーム全員が同じ手順で開発環境を起動できる

## 実装済みの試作機能

- タスクの登録・一覧・編集・完了／未完了切り替え
- グループの作成・名前変更・削除、グループ別の見出し表示・絞り込み（円グラフ・完了済み一覧も連動）、ツリー全体での所属統一、AIへのグループ名送信
- 深さ制限のないタスクの親子ツリー、折りたたみ・親変更、子から祖先への完了状態の自動連動（親から子へは連動しない）
- 子を持つタスクは見出しとして表示・編集し、未完了の葉の残り時間を集計。AI候補から見出しを除外
- 一覧から2段階確認でタスク・子孫を削除し、祖先の完了状態を再計算。取り組み履歴は保持
- やること一覧での達成状況（完了・未完了の円グラフ）表示
- 調子の5択アンケート（少し疲れてる・疲れてる・普通・少し元気・元気）の入力と保存
- ローカルはSQLite、公開環境はSupabase（PostgreSQL）でタスク・調子・予定・履歴を保存
- 空き時間・場所による候補の絞り込み、生成AIによる理由付き提案
- 候補または休息の選択と、選択時の調子・タスク名のユーザー別履歴保存

アカウント登録・ログイン・ログアウトとユーザー別管理を実装。端末カレンダーの選択・予定時間取り込み（開発ビルドが必要）、Webでの予定手入力、空き時間への反映も実装。実機カレンダーの動作確認は未実施。
旧匿名データは保持し、新規アカウントには自動割り当てしない。
疲労度は当面、5択アンケートの自己申告を利用し、自動推定は行わない。
Google等への直接OAuth連携、パスワード再設定、フィードバック学習、通知、課金は今後の作業とする。
API設定手順とデータ送信範囲はREADMEを参照する。
